# Движок и сцены

## Почему так устроено
Ролик — это HTML-страница, но **не анимация в реальном времени**. Каждый кадр вычисляется функцией `render(t)`: по времени `t` выставляются стили, тексты и позиции. `scripts/render.py` вызывает `render(i/30)` для каждого кадра и снимает скриншот через Chromium (CDP), кадры уходят в ffmpeg. Отсюда главные свойства:
- кадры не пропадают и не дёргаются, как бы медленно ни шёл рендер;
- превью в браузере (`render(12.4)` в консоли) совпадает с итоговым видео;
- любой момент можно снять отдельным кадром для проверки.

Поэтому в сценах нельзя: CSS `transition`/`animation` (их глушит base.css), `setTimeout`, `requestAnimationFrame`, `Date.now()`, `Math.random()` во время render. Случайность — только `E.rng(seed)` на этапе build.

GSAP допустим только в детерминированном виде: таймлайн с `paused: true`, внутри `scene(t)` — `tl.seek(t)`. Но всё нужное уже есть в движке, лишняя библиотека не нужна.

## Файлы проекта
```
video.html   сцены ролика (из templates/starter.html)
plan.js      длительность, реплики, музыка — единый источник для страницы и скриптов
cues.js      заглушка до озвучки; после align_vo.py — window.CUES (субтитры) и window.SYNC (время слов)
tmap.js      заглушка; после retime.py — window.TMAP (карта времени ускоренной версии)
engine.js    движок (не редактировать под конкретный ролик)
processing.js  анимация тёмного экрана обработки (нейтральная; для продукта с собственным лоадером — повторите его)
base.css     компоненты на токенах бренда (общее для продукта — в brand/brand.css, сцено-специфичное — в <style> video.html)
brand/       бренд-профиль: brand.css, fonts/, logos/ (снимок профиля проекта)
```
Порядок подключения в `<head>`: `brand/brand.css` → `base.css` → `plan.js` → `cues.js` → `tmap.js` → `processing.js` → `engine.js`.

## Параметры страницы
`?fmt=h|v` — формат · `&subs=0` — без субтитров (вторая версия ролика) · `&tmap=0` — игнорировать `tmap.js`, исходный темп · `&preview=1` — превью в браузере (кадр вписан в окно, ползунок, пуск; `&t=12.4` — открыть на моменте). В `render.py` — через `--qs`, например `--qs subs=0` или `--qs "subs=0&tmap=0"`.

## Полотно
Размер интерфейса — `PLAN.canvas` (по умолчанию `[1600, 960]`). Движок выставляет CSS-переменные `--cw`/`--ch`; `#app`, `#app2`, `.view`, `.topbar` их используют. Под продукт с широким или компактным интерфейсом меняйте `canvas`, а не масштаб камеры: так текст интерфейса остаётся в своих логических пикселях. Центр полотна для камеры — `[CW/2, CH/2]` (`E.CW`, `E.CH`).

## Слои кадра (снизу вверх)
```
#intro, #introT     хук и белый экран-заставка (вне полотна)
#stage > #app       интерфейс CW×CH — его двигает камера; rounded + overflow:hidden
#fdim               затемнение ВСЕГО кадра (z 4): E.dim(.86) — обработка, E.dim(.45) — модалка
#stage2 > #app2     верхний слой (z 5): тёмные экраны (.proc), модалки (.csi), курсор и рябь.
                    Движок копирует на него transform и opacity #app и display #stage → он едет вместе с камерой
#endcard            финал (z 6)
#subL               субтитры (создаёт движок; скрыт при subs=0)
```
**Почему затемнение не внутри `#app`.** Если тёмную подложку положить внутрь скруглённого, обрезанного полотна, на краях окна сглаживание пропускает белый фон: при движении камеры по краю бегает и мерцает светлая рамка (так было на одном из первых роликов). Затемнение на уровне кадра + содержимое над ним в `#app2` этот шов убирают. Проверка — скан яркости по краям кадра на тёмных кадрах (см. pitfalls.md).

## API (`window.E`)
| | |
|---|---|
| `E.CW`, `E.CH` | размер полотна из `PLAN.canvas` |
| `E.start({build, setup, scene})` | запуск; READY выставится после шрифтов, картинок и `setup` |
| `build(E)` | один раз: создать повторяющиеся элементы (карточки, списки, метки, сетку хука, `Processing(...)`) |
| `setup(E)` | замеры и пути: `E.measureAt(t)`, `E.rect(id или элемент)`, `E.camera(kfH, kfV)`, `E.cursor(keys)`, `E.clicks(times)` |
| `scene(t, E)` | состояние DOM на момент t (исходное время сцены). В `E.MEAS` — показать всё, что нужно измерить, без смещений и прозрачности |
| `E.dim(x)` | затемнение кадра 0..1 на этот кадр (берётся максимум из вызовов) |
| `lin(t,a,b)` | 0→1 на отрезке [a,b] |
| `eout(x)`, `eio(x)` | кривые: появление / перемещение |
| `env(t,a,b,fi,fo)` | «конверт»: вход за fi, удержание, выход за fo — поповеры, тосты, панели |
| `bump(t,a,b)` | 0→1→0 — «нажатие» кнопки, вспышка |
| `stagger(t,t0,i,step,dur)` | прогресс i-го элемента каскада |
| `typed(t,a,b,text)` | срез текста для эффекта печати |
| `markup(text, n, segs, sel)` | HTML первых n символов с подсветкой фрагментов `segs=[{a,b,p,id}]`; `sel=true` — «выделить всё» перед перепечаткой |
| `grad(angle)` | переливающийся conic-gradient для `.gw .ring` и `.glow` (угол `t*55`); цвета — `--ring-stops` бренд-профиля |
| `plural(n, ['поставщик','поставщика','поставщиков'])` | склонение для русских счётчиков (для других языков — своя функция в сцене) |
| `blink(t)` | мигание каретки |
| `show(el, cond, display)` | display none/… — возвращает cond |
| `css(el, {...})`, `fmtN(1284)` → «1 284», `rng(seed)` | утилиты |
| `sync('p3:объяснение', 14.6)` | время слова из озвучки (после align_vo.py), иначе запасное |
| `toScene(tn)` | время кадра → исходное время сцены (карта tmap.js) |
| `V`, `W`, `H` | формат: `V=true` — вертикаль |

Камера, курсор с рябью кликов, затемнение кадра, субтитры (`window.CUES` или оценка по тексту реплик) рисуются движком — в сценах их не трогать. Титры-плашки движок умеет (`PLAN.titles`), но в роликах их больше не используем.

## Ускоренная версия (tmap.js)
`retime.py` строит карту `[новое время, исходное время]`: речь ускорена, паузы короче. Движок вызывает `scene(toScene(t))`, поэтому **сцены пишутся один раз, в исходном времени**, с теми же `E.sync` — ускоренная версия получается без правок `video.html`. `window.DURATION` берётся из карты.

## Как строить сцену
Сцена — это интервалы времени, внутри которых элементы получают прогресс:
```js
scene(t, E){
  const {$, lin, eout, eio, env, show, markup, grad, MEAS: M} = E;
  if (show($('vStart'), M || t < T.res, 'flex')) {
    const p = M ? 1 : eout(lin(t, 3.9, 4.35));                              // появление поля
    E.css($('fld'), {opacity: p, transform: `translateY(${(1-p)*16}px)`});
    $('fRing').style.background = $('fGlow').style.background = grad(t*55); // перелив
    const n = M ? Q.length : Math.floor(lin(t, 5.0, 7.05) * Q.length);      // печать
    const h = markup(Q, n, SEG); if ($('fTx')._h !== h) { $('fTx').innerHTML = h; $('fTx')._h = h; }
  }
  const k = M ? 0 : eout(lin(t, 13.0, 13.35)) * (1 - eio(lin(t, 17.75, 18.1)));
  E.dim(.86 * k);                                                            // тёмный экран обработки
  if (show($('proc'), k > .001, 'flex')) { $('proc').style.opacity = k; PV.render(t, 13.45, TD); }
}
```
Правила, которые экономят переделки:
1. Состояние — чистая функция t: одинаковый t → одинаковый кадр. Классы и innerHTML меняйте только при изменении (`el._on !== on`, `el._h !== html`), чтобы не дёргать DOM каждый кадр.
2. Все времена событий держите рядом и считайте от реплик: событие на экране совпадает со словом, которое его называет — `E.sync('p3:слово', запасное_время)`. Метка не может появиться раньше, чем допечатан её фрагмент: `Math.max(конец_печати + .2, E.sync(...))`.
3. Перед любой камерой — замер. `setup` вызывает `E.measureAt(t)` в момент, когда нужный экран открыт, и берёт `E.rect(...)`: `cx, cy, x, y, w, h` в координатах полотна (одинаковых для `#app` и `#app2`). Цели камеры и курсора строятся из этих точек; позиции поповеров («под значком ℹ») и меток под фрагментами запроса — тоже из замеров.
4. Элементы, скрытые `display:none`, имеют нулевой размер — в `MEAS` их нужно показывать (панель подсказок, модалку, приглашение, сообщения чата).
5. Абсолютно позиционированный элемент с `left:50%` и центровкой должен иметь `width:max-content`, иначе текст переносится на половине ширины.
6. Курсор `[t, x, y, opacity]`: появиться в стороне (opacity 0→1), подлететь к цели за 0.3–0.5 с, клик через 0.1–0.15 с после прибытия, остаться 0.2–0.3 с, улететь с исчезновением. Время клика — в `E.clicks`. Курсор живёт в `#app2` — он виден и над модалкой.
7. Новые экраны — отдельные `.view` внутри `#app`. Смена стартового экрана на результаты — **под тёмным экраном обработки**: `vStart` держится до `T.res`, `vRes` включается в `T.res`, затемнение уходит через 0.15–0.5 с, элементы выдачи въезжают с `T.res + .3`.
8. Всё, что должно быть над затемнением (тёмный экран, модалки), — в `#app2`, не в `#app`.
9. Модалка: камера начинает наезд в момент клика, модалка проявляется на середине наезда (а не после) — иначе кажется, что она «догоняет».

## Производительность
Рендер ≈ 0.07–0.15 с на кадр (30 кадров/с ролика → 2–5 мин на минуту видео на формат). Держите DOM лёгким: не больше пары сотен элементов, SVG без фильтров-размытий на больших площадях. `filter: blur` допустим на хуке и на свечении поля.
